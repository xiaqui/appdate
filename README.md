# Release Store — 個人用 Android アプリストア

GitHub Releasesを配布元として、登録した複数のpublic/privateリポジトリのAPKを端末で確認・更新する試作です。Android 6〜10（API 23〜29）が主要対象です。

## 初回設定

1. [検収用プレリリース](https://github.com/xiaqui/artifact/releases)で、目的の `store-preview-<SHA>` にある 版入りAPK（今回は **ReleaseStore-v0.6.0-preview.apk**） をログイン済みブラウザから開きます。ストア版のIDは `jp.xiaqui.artifact.store.preview`。旧Installer版と並行導入でき、旧版の保存データは旧版から開けます。
2. 起動して「リポジトリを登録」に `owner/repo` またはGitHub URLを貼り付けます。「最新の対象にプレリリースも含める」は登録ごとに変更できます。
3. メニューの「設定」でContents読み取り権限の共通PATを登録します。GitHub側で許可した複数repo・新規repoに適用されます。公開repoは匿名を優先し、アクセス拒否・制限時に共通PATを使用します。「個別PATの設定・再認証」はそのrepoだけの例外です。個別PAT解除は共通PATへ戻り、共通PAT解除は個別設定を保持します。どちらもAndroid Keystoreの鍵で暗号化し、バックアップ対象外に保存。鍵喪失時は該当設定を再入力してください。0.4.1のメモリにだけあったPATは初回登録が必要です。

## 更新と過去版

トップ画面の「一括更新確認」、または個別repoの「更新を確認」を押します。下書きを除くAPK付きReleaseを公開日時順に表示します。プレリリースを除く設定では正式版だけが対象です。取得日時とエラーを表示し、通信失敗後も最後に取得した履歴を利用できます。

トップはアプリ名・導入版 → 最新版・更新状態をまとめたタップ可能な行です。「前回」は最後の成功時点の版情報です。一括確認は成功・更新候補・同一版・失敗のrepo数を表示します。中断した確認は未完了として残ります。行をタップすると確認日時・最終成功日時、認証・再試行、Release履歴と保存操作が開きます。Asset詳細でID・提供されているSHA-256を確認できます。登録がゼロでもメニューから保存済みAPKを開けます。

404の詳細にはRelease一覧／タグ／Asset本体／転送先と、該当リクエストの認証有無を表示します。公開repoに公開済みReleaseがないと一覧は空で成功する一方、存在しないタグ・Assetや閲覧権限のないprivate repoは404になり得ます。repo名、公開範囲、選択した対象、PATのrepo指定とContents権限を確認してください。トークン・完全URLは診断に記録しません。

自動取得が有効かつ通信条件を満たす場合、単一APKの最新Releaseを一時取得してpackageName・アプリ名・versionCode・署名・対応OSを調べます。一括更新確認だけではAPKを取得しません。通信量はAPKサイズに依存します。同じAssetの検査結果は次回も利用します。残りの候補と過去版は「APK情報を確認」で個別に解析できます。複数APKは明示的に選択してください。ABI・split構成の完全な判定および分割APKの一括導入は対象外です。

「保存してインストール確認へ」で選択したAPKを取得・検査し、永続保存します。確認画面で「標準インストーラで開く」を押してください。Android 6はPackageInstaller.Session、7以降はFileProviderを使用。Android 8以降の初回は「この提供元を許可」を設定し、戻ってもう一度押します。6/7はOSの提供元不明アプリ設定に従います。

更新状態は実APKと端末のpackageName、数値のversionCode、署名証明書から判定します。現署名が違う場合は「署名不一致の可能性」と表示します。署名ローテーション、ABI、SDK要件など、導入可否の最終判定はOSに従います。旧版の通常の上書きは制限されます。手動でアンインストールすると対象アプリのデータが消えます。ストアにアンインストール操作はありません。自動ロールバックや設定移行はPhase 2です。

## 保存・障害時

保存先はアプリ専用の `files/apks/`。1 APKは128 MiBまで、1パッケージ3世代・全体24件・512 MiBまで保持します。上限時は「保存したAPK」から削除対象を選びます。手動保存・取り込みの自動削除はありません。自動取得分の整理方針は下記参照。ストアの保存履歴にはrepo、タグ、Asset識別子、packageName、バージョン、保存日時を記録します。インストールのキャンセル後も同じAPKを再度開けます。登録削除はAPKを保持します。

403/429の利用制限は時間をおいて再試行、401/404ではrepo・権限・期限を確認して再認証してください。API認証は最初の api.github.com 宛に限定し、署名付き転送先へのAuthorizationを外します。GitHub Mobileのセッションは使用しません。1リポジトリ3,000 Release、1 Release 1,000 Assetまで。端末ストレージ不足・破損APK・署名不一致は各段階で表示します。

従来のRelease共有、ファイル選択・ZIP抽出は補助機能です。アプリが作ったZIPと一時コピーは処理後に削除し、選択APKと利用者の元ファイルを保持します。

## 配送・署名

GitHub Actionsで単体テスト、lint、API 23/29試験、APKの署名・minSdkを検査し、SHA単位の検収用プレリリースへ添付して再取得・バイト照合します。Actions ArtifactはCI内の受け渡し用です。同じタグのAssetを別バイナリで上書きしません。

配送は既存の固定鍵・alias `xiaqui` を必須とし、0.4.1の証明書SHA-256とも照合します。Secrets未設定や指紋不一致なら配送は失敗します。同一IDでも以前の一時debug鍵ビルドとは署名が異なります。

## 実機検収

- 公開・非公開repoを登録し、個別・一括更新、編集・削除、通信を切った状態のキャッシュ、プロセス終了後の認証維持と明示解除を確認。
- 単一・複数APKのアプリ名、packageName、versionCode、導入済み版を確認。プレリリース表示を切り替え、過去版を選択。
- 旧版・署名違いの表示を確認。Android 6/7と8以降でOS確認画面を開き、キャンセル後の保存、再起動後の再試行を確認。

JDK 17、Gradle 8.9、Android SDK 35。ローカル検証は `gradle testDebugUnitTest lintDebug assembleDebug`、端末試験は `gradle connectedDebugAndroidTest`。エミュレータの自動試験と物理端末の検収は区別します。

Release・更新確認・保存日時は表示時に端末のタイムゾーンで yyyy/MM/dd HH:mm に変換します。保存したAPKはメニューの一つの画面で扱い、端末ファイルとGitHub取得分の出所を表示します。記録のない旧APKは「旧保存分」と表示し、ファイル欠落時も履歴を保持します。APK詳細では実ファイルの署名を確認できます。別applicationIdの旧Installerはアプリ専用領域が異なるため、自動移行の対象外です。

## 正式Release

実機検収済みのAPKを再ビルドせず昇格します。対象の版・元SHA・サイズ・APKと証明書の指紋は `.github/release/accepted.json` を参照してください。mainの **Promote accepted APK** でpublishを明示するか、配送設定更新のマージコミットに `[publish-stable]` を指定します。PRでは読み取り検証のみ行います。既存の公開Assetを差し替えず、ドラフトから再取得してビルド済みAPKとの一致を確認してから正式公開します。


## 自動更新確認・通知（0.6.0検収用）

起動時はキャッシュを先に表示し、裏で登録repoを確認します。15分以内の起動・画面回転では再確認を省略。OSのJobSchedulerで約6時間ごとにも確認し、Doze・省電力・強制停止等では延期されます。設定の「自動処理を一時停止」で停止できます。厳密な時刻や画面OFF中の常時動作は保証しません。

APK自動取得・Wi-Fi限定は初期値ONです。メタデータ確認はモバイル回線でも行います。最新ReleaseのAPKが1個の場合だけ取得して実パッケージ・版・署名・対応OSを調べ、端末に導入済みの互換更新だけ永続保存します。未導入・複数APK・署名違い・非対応/不明OSは自動保存しません。初回検査にはAPK相当の通信量が必要です。解析結果はAsset ID/サイズ/更新日時/SHA単位で再利用し、解析済みのOS不明を繰り返し自動取得しません。詳細から手動で再解析できます。

「一括更新確認」はメタデータのみです。「未取得の更新を一括ダウンロード」は検査済み更新候補を取得し、保存済み実体は照合して再利用します。Wi-Fi限定を超える場合は最大通信量と今回だけの許可を表示します。通信断・停止・容量上限は取得済みAPKを保持して保留/失敗を表示し、手動操作または次の定期確認で再試行できます。未解析APKは詳細の「APK情報を確認」、またはWi-Fiでの自動検査を利用してください。

準備完了通知は、1件ならAPK確認画面、複数なら保存APK一覧を開きます。必ず利用者が「標準インストーラで開く」を押してOS確認を行います。通知を消しただけでAPKは削除しません。インストールキャンセル後・オフラインでも保存APKを開けます。通知禁止時は設定から許可するか保存APK一覧を利用してください。Android 8以降は通知チャネル、13以降は通知許可に対応。端末再起動後は準備済み通知を再照合します。

保存上限は従来通り単体128 MiB、1パッケージ3世代、全24件/512 MiBです。上限が迫った際は、自動取得かつ導入済みの古いAPKから整理できます。手動保存・取り込み、インストール待ち、現在開いているAPK、パッケージごとの唯一の互換復旧候補は保護します。最後の復旧候補は導入版以下・同一署名のうち最も新しい保存版です。安全な対象がなければ取得を保留。自動整理後も出所・版・日時の履歴を残します。通知から開く間は一時保護し、手動で「保存」を選んだAPKは恒久保護します。

一覧のアプリ名横は検査済みAndroidManifest.xmlのminSdkを表示します。targetSdkは上限ではありません。maxSdkが明示されないAPKは `Android 6+` のように下限だけ表示し、未解析・複数APK・不明は要確認とします。Android 6でも公開APIと境界検証したAPKマニフェスト読取で対応します。導入版は保存履歴によらずPackageManagerの実インストール状態から照合し、表示名が変わっても同じpackageName/署名として扱います。packageNameの異なるAPKは旧アプリの更新に使いません。

repo改名・owner移動の安定ID追跡はこのmain系列では未対応です。API転送時は追跡不能を表示して旧登録・履歴を保持します。新名で別登録してください。旧登録の名前編集は改名移行として使用しないでください。PAT自動登録PR #4・外部Intent作業は別ブランチのままです。

実機検収は、Z3TC(Android 6)/Z4T(Android 7)/Android 8〜10で起動・画面OFF・Wi-Fi/モバイル切替・通知タップ・インストールキャンセル・3世代上限を確認してください。実PATの失効/組織承認、OEM省電力、複数の実アプリ（Forge/IP Messenger/Nearby Games）の導入版表示は実機未検証です。単体・エミュレータ試験と実機合格は区別します。
