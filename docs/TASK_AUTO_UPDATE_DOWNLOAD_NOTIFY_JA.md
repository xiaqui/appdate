# TASK — 自動更新確認・無人APK取得・通知インストール

作成: 2026-11-14
状態: 次期実装仕様。PAT自動登録PR #4とは別作業。
対象: AppDate（xiaqui/appdate） / Android 6〜10（API 23〜29）

## 目的
GitHub Actionsが公開した各repoのGitHub ReleasesをRelease Storeが検知し、ユーザーの操作なしで更新APKを取得・保存する。インストールは無人実行せず、更新準備完了通知をタップしたときにAndroid標準インストーラへ進む。現行の手動「一括更新確認」「更新を確認」は残す。

## 仕様
1. 起動時に登録repoの更新を自動確認する。画面表示は保存済みキャッシュを先に表示し、通信を待って起動を塞がない。短時間の再起動・画面回転で無駄な再取得をしない。確認中・最終確認・失敗・キャッシュを区別する。
2. バックグラウンドでも端末・OSが許す範囲で定期的に更新確認し、新しいAPKを自動ダウンロードする。Android 6〜10のDoze・省電力・バックグラウンド制限に従い、厳密な実行時刻や常時動作は保証しない。起動時の確認は定期処理とは別に機能する。
3. 自動ダウンロードは初期値ON、Wi-Fi接続時のみを初期値ON、モバイル通信では初期値OFFとする。設定から変更・一時停止できる。通信断・容量不足・認証切れ・レート制限は安全に再試行し、重複ダウンロードしない。
4. 更新候補は現行のpackageName、versionCode、署名等による判定を再利用する。Releaseに複数APKがある場合、対象APKを一意かつ安全に特定できないときは勝手に選択・導入しない。既存のプレリリース設定、共通/個別PAT、公開/非公開repo、API制限、キャッシュを維持する。
5. ダウンロード完了後、既存の永続APK保存領域・履歴へ整合的に登録し、APKのサイズ、破損、パッケージ名、バージョン、署名を検査する。検査できない・不一致のAPKをインストール待ち通知へ進めない。通信中断・再起動後も破損した途中ファイルを完成扱いしない。
6. 更新準備完了を通知する。単件はアプリ名とバージョン、複数件は件数を表示し、通知タップで対象APKの確認画面または更新一覧へ遷移する。そこから標準インストーラを起動する。ユーザーの確認なしにインストールしない。Android 8以降の「この提供元を許可」、Android 6/7の提供元不明アプリ設定に従う。通知権限と通知チャネルは対象APIで適切に扱う。
7. 既存の保存上限「1パッケージ3世代・全体24件・512MiB・単体128MiB」を維持する。3世代保持を新規実装し直さない。自動取得の容量不足対策として、自動取得分の最古世代から安全に整理できる設計を追加する。ただしユーザーが手動で保存・取り込んだAPK、インストール待ち、現在ダウンロード中、唯一の復旧候補、履歴を黙って削除しない。安全な削除対象がなければ取得を保留し、理由を表示する。削除方針をUIとテストで明確にする。
8. インストールキャンセル後は保存APKを再度開ける。通知の重複、既にインストール済みになった更新の通知残留、アプリ再起動後の二重処理を防ぐ。オフラインでも取得済みAPKからインストーラを起動できる。
9. トップに「未取得の更新を一括ダウンロード」ボタンを設ける。自動取得が有効でも、通信失敗・一時停止・Wi-Fi待ちからユーザーが明示的に再取得できるようにする。既に保存済みの最新版は再取得せず、更新候補のみ対象とする。手動実行も署名・容量・重複・通信制限の安全策を共通化し、進捗・成功/失敗・保留件数を表示する。モバイル通信でWi-Fi限定設定を超える場合は通信量と確認を明示し、黙って設定を無視しない。「一括更新確認」（メタデータ確認のみ）と区別して表示する。対象がなければ無効化する。
10. アプリ名（APKの表示ラベル）が変わっても、同じpackageNameと互換署名なら同一アプリとして履歴・保存APK・更新判定を継続する。表示名は最新の検査済みAPKのラベルを優先し、旧名は履歴に保持する。表示名で重複登録・別アプリ扱いをしない。packageName変更は別アプリとして扱い、無断で旧アプリの更新・データ移行を行わない。repo名/ownerの変更は可能ならGitHub repoの安定IDで追跡し、URLや表示名だけで重複・履歴消失を起こさない。追跡不能なら明示して手動再登録を案内する。
11. 一覧の**アプリ名の横**に対応Android OSを簡潔に表示する（例: `Android 6+`）。APKから確認できるminSdkVersionを下限としてOSバージョンへ変換する。上限は明示されたmaxSdkVersion等の信頼できる情報がある場合のみ表示し、なければ勝手に「Android 6〜10対応」と断定しない。targetSdkVersionは対応OS上限と混同しない。複数APK・未解析・解析失敗・OS適合不明は「要確認」等と表示し、詳細画面でminSdk/targetSdk/maxSdk（取得可能な範囲）と出典を示す。端末OSが下限未満なら非対応を視覚的に示し、自動ダウンロードの対象から除外する。表示名変更後もOS情報を正しいAPKに紐付ける。
12. 自動更新の対象はRelease Storeが登録済みのrepoに限定する。PATによるrepo自動登録PR #4が未mergeの場合は、その未merge実装を前提にコードを書かず、現行mainの登録方式で成立させる。PR #4がmergeされた場合は最新mainへ追従する。外部Intent連携branchとも混在させない。

13. **端末の実インストール状態を正本として照合する。** Release Store経由で取得・インストールしたかに関係なく、登録repoのAPKからpackageNameを安全に特定できた場合、Android PackageManagerで端末上の実際のインストール有無・versionName・versionCodeを取得し、トップの「導入」表示と更新判定へ反映する。保存APK履歴やRelease Store経由の操作履歴は別に保持し、保存しただけで導入済みと判定しない。端末に導入済みのForge・IP Messenger・Nearby Games等が「導入 不明」となる実機報告を回帰テストに含める。APK未解析・複数packageName候補・端末照合失敗時は推測せず「未確認」と表示し、未インストールと断定しない。起動・更新確認時、インストール後の復帰時に状態を再照合する。Android 6〜10で利用可能なAPIを使用し、他アプリの状態確認に不要な権限を要求しない。

## トップ画面の表示方針（2026-11-16 社長確定）

**PR #6の自動処理によってトップのアプリ一覧に新しい進行表示・状態説明・常設ログを増やさない。** 起動時や定期更新の通信は静かに裏で行い、通常の一覧と既存操作を優先する。「確認中」「ダウンロード中」「Wi-Fi待ち」「自動処理の最終結果」などを毎回トップに別行で追加しない。処理中の画面全体の置き換えや進捗の連続再描画も行わない。必要な情報は認証/自動更新の設定画面、対象アプリの詳細、更新準備完了時の通知などに置く。障害や保留の詳細も参照先で確認できるようにし、黙って握りつぶさない。

既存の「一括更新確認」など**ユーザーが明示的に起動した手動処理**の結果表示は維持してよいが、自動処理の経過をそれに混ぜたり、トップの表示行を増殖させたりしない。既存の「未取得の更新を一括ダウンロード」操作は仕様9の範囲で維持する。更新対象がある場合の必要最小限の視覚的な強調は許容し、件数・状態を繰り返し表示する冗長なバナーや常設進行バーは作らない。

PR #6の実装では、トップ画面に追加されていた `label(automatic.state())` の除去を含めて検収すること。メイン画面で長時間動作させても、進行メッセージが蓄積せず、一覧の並び・操作・スクロールを妨げないことを確認する。

## バージョン番号の表示（2026-11-16 確定）

トップのアプリ一覧では、導入済み・最新候補とも **versionNameのみ** を表示し、後ろの `(${versionCode})` を表示しない。例：`導入 0.6.0 → 最新 0.7.0`。詳細画面ではversionCodeを引き続き確認できるようにし、更新可否・インストール互換性の判定には従来どおりversionCodeと署名を使用する。表示だけを変更し、内部の識別・履歴・比較ロジックは変更しない。versionNameが空なら「名称不明」等の表示を維持する。

## トップ画面：下スワイプ更新とAppDate表記（2026-11-16確定）

- トップのアプリ一覧は画面上端から下へ引っ張ると、既存の「一括更新確認」と同じ登録repoのReleaseメタデータ更新を実行する。下方向の通常スクロールとは区別し、一覧が先頭以外にスクロールされているときは起動しない。実行中に重複起動せず、登録がゼロ件なら通信を開始しない。
- 下スワイプ処理中は短時間の標準更新インジケーターのみ使用し、トップ画面に常設の進行ログ・説明文・追加の進捗行を設けず、アプリ一覧を別画面へ置き換えない。完了後は既存の一括更新結果表示と一覧を再描画する。手動「一括更新確認」ボタンも残す。
- ランチャー表示名・アプリのタイトルバー・トップ見出しは **AppDate** に統一する。Android applicationId・namespace・署名鍵・保存領域は変更せず、既存APKへの上書き互換性を維持する。配布APKのファイル名や過去Releaseタグは無断で書き換えない。
- トップの版表示はversionNameのみ、versionCodeは詳細へ。コード値による更新判定はそのまま。

## 非目標
- 無人インストール、root、ADB初期権限付与、Shizuku、Device Owner化。
- Android 12以降の無人更新API。
- GitHub Actionsのビルド・署名・公開方式や他repoのSecretsの変更。
- 全APKの無条件取得、全repoの無条件自動インストール、署名違いの強制上書き。\n- アプリ表示名変更をpackageName変更と同一視すること、targetSdkを対応OS上限と推定すること。
- 既存の手動保存APKや履歴の破壊的移行。

## 実装・検収
1. 最新main、xiaqui/rin/README.md・STYLE.md、AGENTS.md、README.md、TASK.md、既存PR/branchと現在のコードを確認し、同目的のPRがあれば重複作成しない。最新mainから独立branchを作成する。
2. 起動時自動確認、Wi-Fi限定の定期取得、一括手動取得、通知、保存上限、表示名変更・repo改名・packageName変更、対応OS表示と非対応除外、端末の実インストール状態と保存履歴の分離・照合、再試行・中断・再起動・重複防止を単体/統合テストする。Android 6/API23と10/API29のAPI境界を重点確認する。
3. test、lint、CI、独立レビューを実施しP0/P1を修正する。実機検収はZ3TC(Android6)、Z4T(Android7)、Android8/9/10の代表端末で、起動・画面OFF・通信切替・通知タップ・インストールキャンセル・保存上限を確認する。実機未確認は合格扱いしない。
4. commit/pushして独立PRを作成し、**社長の実機検収前にmergeしない**。PR URL、CI、APKの配送先、未確認項目を報告する。配送が必要ならGitHub Releasesの検収用プレビューを利用し、既存署名・版入り命名・Release乱造防止を守る。
