## 目的・確定仕様
社長がGitHub側でfine-grained PATの対象repoを管理するため、Release Store側で二重の選別をしない。**共通PATでAPIから列挙できるrepoを、機械的にすべて登録する。**

1. 共通PATの初回保存・変更後、PATで列挙できるリポジトリを取得し、すべて自動追加する。APKやReleaseの有無、公開/非公開、リポジトリ名によるフィルタは設けない。
2. 事前の選択画面、チェックボックス、登録可否の個別確認は不要。既存登録は重複させず、owner/repoの識別子で照合する。
3. 設定等に「repoを再取得」操作を置く。再取得は**追加専用**。既存登録、repo別設定、保存済みAPK、履歴を保持し、PAT対象から外れたrepoも自動削除しない。
4. 利用者が手動削除したrepoも、後日PATで列挙されれば再取得時に復活してよい。削除抑止リストは不要。
5. Releaseが存在しないrepoは登録自体を成功させ、更新確認時に「配布なし」等と区別して表示する。認証失敗や通信失敗を「配布なし」と混同しない。
6. GitHub APIのページネーションに対応し、複数ページを取得する。重複・大文字小文字・リネーム・アーカイブ等はGitHubの安定IDを利用できる範囲で安全に扱う。失敗時は取得済みの登録を消さず、取得件数・追加件数・失敗理由を表示する。
7. **PATで閲覧できるrepoと列挙APIが返すrepoは一致しない場合がある。** 利用するAPIの認証方式・fine-grained PATでの列挙可能範囲を確認し、取得できたrepoだけを追加する。APIが権限上返さないrepoを「必ず自動登録できる」とは表示しない。従来の手動登録を残す。
8. PATをログ・画面・URL・例外・診断へ漏らさない。最小権限で動作し、401/403/404、レート制限、ネットワーク断、空結果を区別する。権限を増やすことを無条件に要求しない。
9. 初回起動時にPAT未設定なら従来どおり手動登録可能。PAT設定時に一括登録を開始し、再取得は明示操作で行う。既存ユーザーへの移行でデータを消さない。

## 検証・完了条件

- 既存の手動登録・削除・更新確認・共通PAT暗号化保存・repo別PAT・保存APK・外部Intent経路を壊さない。
- Android 6/API23 と Android 10/API29 を中心に単体テスト、lint、CI、独立レビュー、P0/P1修正を実施する。端末固有の挙動は実機検収待ちとして明示する。
- xiaqui/rin/STYLE.mdのRelease乱造防止と版入りAPK名規則に従う。通常pushやdocs変更で新Releaseを作らない。APK配送が必要な場合のみ明示的に実施する。
- **この機能は別PRで作成し、社長の実機検収前にマージしない。** 完了時はPR、CI、検収項目、APIの列挙制限を報告する。

## 非目標
- GitHub上のPAT権限設定をアプリから変更すること。
- Release/APKの有無による自動登録候補の絞り込み。
- 確認画面や登録候補の手動選択。
- PATから外したrepoの自動削除。
- 他repoの署名Secrets・GitHub Actionsをこのタスクから変更すること。
