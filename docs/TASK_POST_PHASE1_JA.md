# Artifact 実機検収後の改善タスク（認証保持・一覧UI）

作成日：2026-11-13

> Phase 1 の実機試用で判明した使い勝手の改善。現行 `TASK.md` のPhase 1実装を壊さず、**独立した小規模PR**で対応する。Phase 2のロールバックや検収管理は対象外。

## 実機で確認した事実と未確定事項

- Release Storeは実機で起動し、自己リポジトリのReleaseを取得・インストールできた。
- 一覧には導入済み `0.3 (3)`、最新APK `0.3 (3)`、同一版と表示されたが、長いタグ・APK名・packageNameに埋もれ、版が分かりにくい。
- 同じ一覧に「取得失敗・GitHub HTTP 404」が表示された。前回取得情報は残っていた。**404の原因がPAT消失と確定したわけではない**。公開/非公開、認証有無、APIエンドポイント、権限、Releaseの有無を切り分ける。
- 現状READMEによるとPATはメモリのみで、プロセス終了後に再入力が必要。日常利用に不便。

## P1：PATの安全な永続保持と404の原因切り分け

1. Android 6〜10（API 23〜29）で動くAndroid Keystoreを利用した認証付き暗号化保存を実装する。秘密鍵はKeystore管理、PAT平文をSharedPreferences、ログ、URL、バックアップ、診断出力へ書かない。保存は端末内のみ。必要なバックアップ除外を設定する。
2. repoごとにPATを管理し、登録・更新・削除、認証解除、期限切れ時の再入力ができる。再起動・プロセス終了後も再認証不要とする。ユーザーが明示的に解除したトークンは再使用しない。
3. Keystore鍵の喪失・復号失敗時は安全に認証なし状態へ戻し、ユーザーに再入力を案内する。クラッシュ、平文へのフォールバック、誤ったトークン再使用は禁止。
4. APIの404を一律「トークン切れ」と決めつけない。公開repo匿名アクセス、非公開repo認証あり/なし、無効PAT、権限不足、repo/Release不存在、認証エンドポイント誤りをモックと可能な実環境で検証する。GitHub APIの情報開示制限により404だけでは原因を断定できないことをUIで説明する。
5. 認証ヘッダをGitHub API以外のホストやダウンロード先リダイレクトへ転送しない。既存の安全な取得処理を維持する。PATを含むURLの受理や診断出力を禁止する。

## P1：アプリ一覧の版情報を主役にする

1. 各repoの一覧で**導入済み versionName (versionCode)**、**最新APK versionName (versionCode)**、**更新状態**を短く視認しやすく表示する。未導入、解析前、複数APKで最新版を一意に決められない場合は「不明／未確認」とし、値を推測しない。
2. アプリ名を見出し、repoを補助表示にする。Releaseタグ、APK名、packageName、ビルドSHAなどは詳細画面で参照可能にし、必要な技術情報を削除しない。
3. 同一versionCodeでも異なるビルドが存在し得るため、同一版判定とバイナリ同一性を混同しない。SHA/Asset IDは詳細で確認できるようにする。
4. Android 6の小画面、文字サイズ拡大、複数repo登録時でも読みやすいレイアウトとする。画面全体の刷新は行わない。

## P1：7〜10 repoを一覧できるコンパクトなトップ画面

- トップ画面は**登録済みアプリの一覧と更新状態を一目で確認する場所**とする。7 repo程度を想定し、縦スクロール量と1件あたりの高さを抑える。Android 6のタブレットと小画面端末、文字拡大にも対応する。
- 1件の基本表示は「アプリ名／導入済み版 → 最新版／状態」の**コンパクトな1〜2行**を目安にする。repo名は必要に応じ小さく補足。未解析・複数APKなどは正確な状態を短く表示する。
- Releaseタグ、SHA、APK名、packageName、取得日時の詳細、エラー全文、認証・登録編集・履歴・保存APK操作は**対象行をタップした詳細画面**へ移す。情報を削除せず階層化する。
- トップには「すべて更新確認」、登録追加への導線、更新あり／失敗の目印を残す。全件確認の結果サマリーは簡潔に表示する。
- 既存の画面遷移と機能を維持し、長い名称・日本語・文字サイズ拡大でも操作ボタンが潰れないようにする。7件登録時のスクリーンショット相当のUI検証を行う。
- アプリ一覧を単純に情報削除した画面にしない。**トップ＝一覧、詳細＝操作と技術情報**という役割分担を守る。

## P1：取得エラーを一覧情報から分離

- 一覧では「更新確認失敗（HTTP 404）」等の短い状態を示し、詳細で原因候補・再試行・再認証への導線を表示する。
- **キャッシュされた前回の版情報**と**今回の取得失敗**を明確に区別し、古い版を現在の最新と断言しない。
- 最終取得成功日時と今回の確認結果・確認日時を別々に保持・表示する。

## P2：一括更新確認の結果表示

- 全件確認の終了後に、確認成功件数、更新候補件数、失敗件数、同一版件数を要約する。
- 一部失敗時も成功したrepoの結果を残し、再試行できる。すべて成功したように表示しない。
- 処理中・キャンセル・通信断・再起動の状態表示が不正にならないようにする。

## テスト・完了条件

- PAT保存→プロセス終了→再起動→Release取得、認証解除、鍵喪失、無効PAT、複数repo、匿名公開repo、認証情報漏えい防止を検証。
- HTTP 401/403/404/429、通信断、キャッシュ保持、最終成功日時、一括確認の部分失敗をテスト。
- versionName/versionCode表示、複数Asset、同一versionCode別SHA、7〜10 repo一覧、文字サイズ拡大、Android 6〜10の互換性を検証。
- 既存テスト、lint、ビルド、可能なAPI 23/29エミュレータ試験、独立レビュー、P0/P1修正を実施。
- APKはActionsで検収用GitHubプレリリースに直接配送。固定署名が利用できるか確認し、ビルドSHA、署名指紋、applicationId、versionCode、上書き可否を報告。
- **既存Phase 1のPR・コミット・Releaseを失わない。ユーザーの明示的承認なしにマージしない。** 実機未確認を完了と扱わない。

## 対象外

Forge統合、検収機能、設定バックアップ、一時ロールバック、自動アンインストール、全repoの配送方式変更、全面UI刷新。
